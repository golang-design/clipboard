# Design: telling sensitive content apart

| | |
|---|---|
| **Status** | Implemented |
| **Issue** | [#178](https://github.com/golang-design/clipboard/issues/178) |
| **Prompted by** | midgard, which synced every password its user copied |

## Problem

Password managers mark the passwords they copy, so that clipboard managers,
histories and sync tools leave them alone. Each platform has its convention:

| Platform | Marker |
|---|---|
| macOS | `org.nspasteboard.ConcealedType` or `TransientType` (nspasteboard.org) |
| Windows | `ExcludeClipboardContentFromMonitorProcessing` present, or `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` set to 0 |
| X11, Wayland | the `x-kde-passwordManagerHint` target, valued `secret` |

None of these is MIME-shaped, and `Formats` reports only MIME-shaped types or
ones with a known alias, so every marker was dropped: a program built on this
package could not tell a password from any other text.

## Design

- `Sensitive(ctx, opts...) (bool, error)` asks about the current content.
- `Data.Sensitive` carries the same answer on each value from `Watch`, which
  is how a syncing tool sees copies. It is checked once the change is seen,
  so a copy replaced in the same instant may be judged by its successor.
- Where no convention can be read — iOS, Android, the browser — `Sensitive`
  returns `ErrUnsupported`, not `false`: a caller must not take "cannot tell"
  as "safe to keep".

`Formats` is deliberately unchanged. Reporting every native type through it
would turn UTIs and Windows format names into `Format` tokens whose `MIME()`
is not a MIME type, and every caller would have to learn each platform's
markers — which is exactly the knowledge this package exists to hold.
`AutoGeneratedType` is not treated as sensitive: it says who made the
content, not that it is secret.

Reading the markers is a TARGETS/types query, not a paste, so on X11 and
Wayland it consumes none of a `Loops` limit.

## Not done

Writing: a password tool built on this package could want to *set* these
markers. `WriteAll` with `Register(marker)` already does that per platform; a
portable option can follow if someone needs it.
